## 1. 需求概述
该需求旨在为 `markdown_widget` 引入一套灵活的自定义选择机制，突破原生 `SelectionArea` 的功能局限。核心目标包括：
- 自定义长按后的交互流程（先弹出菜单，后进入选择状态）。
- 支持菜单样式的深度定制。
- 实现“按元素颗粒度”的智能初始选中（如点击标题选中全标题，点击列表选中当前项）。
- 保留灵活的选区调整能力。

---

## 2. 核心挑战评估

### 2.1 交互链路变更 (Difficulty: Medium)
- **挑战**：Flutter 原生的 `SelectionArea` 通常在手势发生时立即启动选择逻辑。需求要求“长按先不选中文字，而是弹出菜单”，这需要拦截或重写原生的手势处理逻辑。
- **解决方案**：可能需要一套自定义的 `SelectionRegistrar` 或通过事件冒泡拦截点按/长按操作。

### 2.2 智能元素定位 (Difficulty: High)
- **挑战**：如何精确判定用户点击的具体 Markdown 元素类型及范围。`markdown_widget` 渲染出的组件树是嵌套的，需要通过渲染对象（RenderObject）或 Key 来反查其对应的 Markdown 节点信息。
- **复杂度**：嵌套元素（如列表中的代码块）的边界判定需要严密的算法逻辑。

### 2.3 自定义菜单与 SelectionArea 的整合 (Difficulty: Medium)
- **挑战**：Flutter 3.27.4 对 `SelectionArea` 的 `contextMenuBuilder` 提供了支持，但需求中的“两阶段”弹出（第一阶段功能扩展，第二阶段才是复制）超出了标准 API 的设计预期。
- **解决方案**：需要解耦 `SelectionArea` 的默认 Toolbar 触发器。

---

## 3. 详细评审建议

### 3.1 架构设计建议
- **策略模式**：建议引入 `SelectionMode` 抽象类，区分 `StandardSelection` 和 `CustomSelection`。
- **Element Resolver**：设计一个解析类，负责将 `Offset`（屏幕点击位置）映射到 `MarkdownElement`。

### 3.2 兼容性与性能
- **版本锁定**：Flutter 3.27.4 提供了较新的选择 API，需充分利用 `SelectableRegion` 和 `SelectionSelectionArea` 的高级属性。
- **性能优化**：由于涉及大量的渲染对象遍历，在大篇幅 Markdown 文档中需注意点击响应的延迟优化。

### 3.3 文档建议补充
- **边缘情况定义**：若点击在两个元素缝隙间如何处理？
- **多选逻辑**：跨元素滑动选择时，UI 反馈是否需要特殊处理（如高亮整个块）？

## 4. 结论
**评审结果：通过（可行，但开发复杂度较高）**

该需求描述清晰，业务场景合理。实现重点在于对 Flutter底层 `Selection` 机制的深度定制和 Markdown 节点信息的反向映射。建议在实现初期先攻克“两阶段菜单切换”和“节点范围识别”这两个核心技术难点。
